# Crack Me If You Can — Securinets ISI

A no-shared-server hash-cracking workshop tool. Every member cracks
hashes with **their own hashcat, on their own Kali VM** — this website's
only job is to generate personal target hashes per tier, verify answers,
run the live leaderboard, and produce the custom wordlist. It never runs
hashcat itself, so it can't choke under load the way a shared terminal
server could.

## How the tiers work

| Tier | Teaches | Source | Notes |
|---|---|---|---|
| 1 | Meet hashcat | Custom wordlist (500 base + everyone's own password) | The command is given outright — this is the "wow" moment |
| 2 | Wordlist choice matters | rockyou.txt | Same command fails; the word isn't in the small custom list |
| 3 | Identify before you crack | SecLists | Different hash algorithm (SHA-256) — pushes them to run `hashid` |
| 4 | What a salt does | rockyou + SecLists combined | Hash ships as `hash:salt` — unsolvable without passing the salt correctly |
| 5 | Why some hashes survive | The 5-6 strongest submitted passwords | bcrypt — intentionally won't crack live; ends in a "mark as complete" button, not a real crack |

Each player gets a **different word per tier**, drawn without replacement,
so the first solver announcing "I got it!" doesn't hand everyone else a
free answer — everyone still has to run their own attack.

## Before the event — replace the placeholder wordlists

`data/sample_rockyou.txt` and `data/sample_seclists.txt` are **small
placeholders** generated for testing — this sandbox has no internet
access to fetch the real files. Before the real event:

1. Get the real `rockyou.txt` (bundled on Kali at
   `/usr/share/wordlists/rockyou.txt.gz` — `gunzip` it) and a real
   SecLists file (`apt install seclists`, or
   `git clone https://github.com/danielmiessler/SecLists`).
2. For speed, use just the first 50k-100k lines of each (rockyou is
   already ordered roughly by real-world frequency, so this keeps every
   tier-2+ crack fast without needing the full 14 million lines):
   ```bash
   head -n 100000 /usr/share/wordlists/rockyou.txt > data/sample_rockyou.txt
   head -n 100000 SecLists/Passwords/Common-Credentials/10-million-password-list-top-1000000.txt > data/sample_seclists.txt
   ```
3. Make sure attendees have **the same rockyou.txt / SecLists files**
   installed locally on their Kali VMs — the server only needs its own
   copy to *pick* words from; participants need their own copy to
   actually run hashcat against.

`data/base_wordlist.txt` (the 500 curated custom-list passwords) was
generated by `data/generate_base_wordlist.py` and is ready to use as-is,
but feel free to hand-edit it or add more club-specific/local terms.

## Running locally

```bash
pip install -r requirements.txt
python3 init_db.py
python3 app.py
```
Visit `http://localhost:5000`. Set `ADMIN_PASSWORD` (env var) before
running for anything beyond local testing — it defaults to `luki-admin`.

## Deploying on Render

1. Push this folder to a GitHub repo.
2. On Render: New → Web Service → connect the repo. `render.yaml` is
   already set up (build installs requirements + initializes the DB,
   start command runs `gunicorn app:app`).
3. Set the `ADMIN_PASSWORD` environment variable in the Render
   dashboard (marked `sync: false` in `render.yaml` so it isn't
   committed to the repo).
4. Once deployed, share the site URL with attendees for `/join`.

## Running the event

1. **Before doors open:** load the real wordlists (see above), confirm
   the site's live at its Render URL, and do a dry run with a few test
   joins.
2. **Registration window:** attendees visit the site, pick a codename +
   test password (big on-screen warning: never a real password), and
   land on a waiting page.
3. **When everyone's in:** log into `/admin` (the admin password, not
   the `/luki` link) and hit **"Close registration & generate tiers."**
   This is the moment that:
   - ranks all submitted passwords by strength
   - holds back the 5-6 strongest as the Tier 5 bcrypt pool
   - inserts everyone else's password into the custom wordlist, at a
     random position between lines 200-300
   - generates every player's Tier 1-4 target hashes
   This can't be undone, so make sure registration is actually done
   before clicking it.
4. **Download the wordlist:** go to `/luki` (no password needed — low
   stakes for this event) and distribute the file to attendees (Discord,
   AirDrop, USB, whatever's fastest) as `securinets_custom_wordlist.txt`.
5. **Everyone plays:** `/play` shows each person their current tier,
   target hash, and (for Tier 1 only) the exact hashcat command to run.
   Project `/leaderboard` on the big screen — it auto-refreshes.
6. **Tier 5 finale:** nobody's expected to actually crack it. The page
   has a "mark as complete" button once they've watched `hashcat`
   struggle and seen the `H/s` counter crater. Talk through *why*
   right there — that's the whole point of this tier.
7. **After the event:** the `crackme.db` file has everyone's plaintext
   test passwords sitting in `plaintext_pending` — wipe or delete the
   database once you're done with it. There's no reason to keep them.

## Notes on the security posture (by design, for this context)

- `/luki` has no auth. For a low-stakes club event where "no one will
  guess the URL and nobody attending is trying to break the admin flow,"
  that's an accepted tradeoff — just don't post the link publicly before
  registration closes (the route itself blocks downloads until then).
- `/admin` **is** password-gated, since closing registration early or
  by accident would be a real problem mid-event.
- Answers are verified by re-hashing the submission and comparing — the
  server never needs to keep the original tier-2/3/4 words around after
  generating a target.
- Tier 1-4 plaintexts do get stored temporarily (`plaintext_pending`,
  and the wordlist itself) — delete the database after the event.
